# Upcoming fixtures and squads

[`schedule_fetcher.py`](schedule_fetcher.py) gets the provider schedule, and [`squad_fetcher.py`](squad_fetcher.py) fetches bounded Cricbuzz series/player rosters. [`cricapi_sync.py`](cricapi_sync.py) provides a short-horizon cricketdata.org fixture source. [`fixture_store.py`](fixture_store.py) and [`squad_store.py`](squad_store.py) validate and atomically publish primary/last-good JSON copies. `upcoming_matches.json`, `upcoming_squads.json` and `injury_status.json` are data snapshots, not source code.

Set `RAPID_API_KEY` for the full provider path or `CRICKET_DATA_API_KEY` for the limited free feed. Run the fetchers from the repository root with the installed Python environment; `refresh_squads.bat --max-requests 4` is the laptop wrapper. The API serves only still-future fixtures and labels provider, series, last-match and pending squad sources. A stale or incomplete feed is reported rather than silently invented. Run `python -m unittest tests.test_squad_fetcher tests.test_series_squads tests.test_last_match_squads tests.test_resilience_and_explanations -v`. See the [Cloudflare operations guide](../../docs/CLOUDFLARE_DEMO.md).
